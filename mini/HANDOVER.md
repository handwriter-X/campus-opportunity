# 校园活动与组队机会池飞书小程序：项目说明文档

版本：v1.0　｜　更新日期：2026-10-15

## 1. 项目概述

本项目是一个运行在飞书移动端的小程序，由两个 Tab 页面组成：

- **校园活动**：展示后端 Agent 从互联网爬取并整理的校园活动，支持搜索、状态筛选和详情弹窗。
- **组队机会池**：展示组队需求，用户可在详情弹窗中点击「申请」，由飞书机器人私信通知需求发布者。

用户的入口有两种：直接从飞书工作台打开小程序，或在与飞书机器人的会话中点击消息卡片的「查看详情」跳转进入。

## 2. 技术栈与框架

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 跨端框架 | Taro 3.6.x（webpack5） | 使用 `--type tt` 编译出字节系小程序产物，飞书小程序可直接导入 |
| UI 框架 | React 18 + TypeScript 5 | 函数组件 + Hooks |
| 样式 | Tailwind CSS 3 + weapp-tailwindcss | 后者负责让 Tailwind 类名在小程序中可用，并把 rem 转为 rpx |
| 运行环境 | 飞书开发者工具 | 用于预览、调试、上传 |
| 网络层 | `Taro.request` 二次封装 | 统一注入 Agent 的 ID 与 Key，统一错误处理 |

说明：Taro 没有专门的飞书平台，这里依赖飞书小程序与 `tt` 小程序的语法和 API 基本一致。个别 API 的表现可能有差异，以飞书开放平台文档为准。

## 4. 构建与工具链

### 4.1 常用命令

```bash
npm install          # 安装依赖
npm run dev:tt       # 开发模式（监听文件变化，自动重新编译）
npm run build:tt     # 生产构建
```

构建产物在 `dist/` 目录，在飞书开发者工具中**导入 `dist` 目录**，而不是项目根目录。

### 4.2 关键配置与注意事项

1. **`project.config.json` 与 `project.tt.json` 要同时修改**，构建时后者会覆盖 `dist` 中的项目配置，只改一个可能不生效。
2. **`setting.es6` 必须为 `true`**。设为 `false` 时，Taro 运行时中的 `const` 不会被降级，会报 `Cannot access '_caf' before initialization`。
3. **`appid` 必须填飞书小程序真实的 App ID**（`cli_` 开头），不能留占位文字。
4. **修改 `.env.*` 或 `app.config.ts` 后，需要停掉并重启 `dev:tt`**，环境变量只在启动时读取，页面和 Tab 配置的热更新也不一定生效。
5. **版本锁定**：所有 `@tarojs/*` 包应保持同一版本。出现莫名的运行时报错时，先执行 `npm ls @tarojs/runtime @tarojs/taro @tarojs/plugin-platform-tt` 检查是否一致。
6. **Tailwind**：`weapp-tailwindcss` 的配置方式随版本变化较大，样式不生效时对照其官方文档中的 Taro + webpack5 章节核对 `config/index.ts` 与 `postcss.config.js`。
7. 紧凑布局的尺寸直接用 `rpx` 内联样式书写，调整时直接改数值。

### 4.3 常见报错速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot access '_caf' before initialization` | 未开启 ES6 转 ES5 | `es6` 改为 `true`，清理 `dist` 重新编译 |
| `invalid appId` | `appid` 是占位文字 | 填入真实 App ID |
| `.js` 文件里 JSON 的冒号标红 | JSON 内容粘贴到了 `.js` 文件 | 放入 `.json` 文件 |
| 胶囊文字偏下 | 行高大于胶囊高度 | 使用 `Pill` 组件 |
| 改了 `.env` 不生效 | 环境变量启动时才读取 | 重启 `dev:tt` |
| 真机请求失败 | 域名未加白名单 | 见 6.4 |

## 5. 页面功能与业务规则

### 5.1 校园活动页（`pages/index`）

- **卡片字段**：活动名称、活动类型、活动时间、报名截止时间、地点、状态。「信息来源」仅在详情弹窗中展示。
- **状态**：由前端按当前时间与 `deadline` 实时计算。当前时间晚于截止时间为「已截止」，否则为「可参与」。
- **排序**：按截止时间距离当前时间由近到远排列，截止最近的在最上面。
- **默认筛选**：只显示「可参与」。
- **搜索**：活动名称关键词、活动类型、状态、报名截止日期（筛出所选日期之前截止的活动）。点击「查询」后生效，「重置」恢复默认。
- **详情弹窗**：展示卡片全部信息、来源和活动介绍。
- **深链**：接收启动参数 `activityId`，数据加载后自动弹出对应活动的详情。

### 5.2 组队机会池页（`pages/team`）

- **卡片字段**：项目名称、已集结 x 人、需要招募 x 人、招募角色、截止时间、需求状态。
- **招募角色**：后端给什么文本就展示什么，前端不做标签分类。
- **状态**：后端标记结束（`closed`），或已超过截止时间，任一成立即为「需求结束」，否则为「仍在招募」。
- **排序与默认筛选**：同活动页，默认只显示「仍在招募」。
- **搜索**：一个输入框同时匹配项目名称、招募角色和详情字段（项目介绍、能力要求、周期、发布者），多个关键词用空格分隔且需全部命中。直接输入「仍在招募」或「需求结束」会按状态搜索。
- **详情弹窗**：先用列表数据立即展示，再请求详情接口补全。弹窗内可填写留言并点击「申请」。

## 6. 前后端交接

### 6.1 交接边界

| 前端负责 | 后端 Agent 负责 |
| --- | --- |
| 页面展示、搜索、排序、状态计算 | 爬取、清洗、存储活动与组队需求 |
| 携带凭证请求接口 | 校验 Agent API ID / Key |
| 提交申请、传递飞书登录 code | 申请记录、防重复、识别申请人 |
| 接收深链参数并弹出详情 | 调用飞书接口发送消息卡片与私信 |

小程序是**前端主动请求**后端，不是后端向前端推送。爬到的新数据先入库，前端在打开页面或下拉刷新时拉取。要做到实时提醒，需要后端通过飞书机器人发消息卡片（见第 7 节）。

### 6.2 接口清单

接口路径集中在 `src/config/agent.ts` 的 `endpoints`，按实际情况修改。

| 用途 | 方法 | 默认路径 | 请求体 | 返回 |
| --- | --- | --- | --- | --- |
| 校园活动列表 | POST | `/v1/activities/list` | `{}` | 活动数组 |
| 组队需求列表 | POST | `/v1/teams/list` | `{}` | 组队需求数组 |
| 组队需求详情 | POST | `/v1/teams/detail` | `{ id }` | 单个组队需求 |
| 提交申请 | POST | `/v1/teams/apply` | `{ teamId, message, userCode }` | `{ message }` |

### 6.3 鉴权与响应约定

请求头由 `src/services/request.ts` 统一注入：

```
X-Agent-Id: <API ID>
Authorization: Bearer <API Key>
Content-Type: application/json
```

响应外层结构约定为：

```json
{ "code": 0, "message": "ok", "data": ... }
```

`code` 为 0 表示成功。以上均为占位约定，若后端协议不同，只需改 `request.ts` 与 `endpoints`。

### 6.4 数据字段约定

**校园活动**

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识，须与机器人卡片中的 `activityId` 一致 |
| `name` | 活动名称 |
| `type` | 活动类型（竞赛、讲座、志愿实践等） |
| `activityTime` | 活动时间 |
| `deadline` | 报名截止时间，**必填** |
| `location` | 地点 |
| `source` | 来源 |
| `description` | 活动介绍 |

**组队需求**

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识 |
| `name` | 项目名称，**必填** |
| `currentCount` | 目前团队人数 |
| `recruitCount` | 招募人数 |
| `roles` | 招募角色，字符串或字符串数组 |
| `deadline` | 截止时间，**必填** |
| `status` / `closed` | 是否已结束 |
| `description` / `requirements` / `duration` / `publisherName` / `publishTime` | 详情字段 |

**时间格式**：推荐 `YYYY-MM-DD HH:mm`。前端适配层同时兼容时间戳（秒或毫秒）、ISO 格式和纯日期，纯日期的截止时间按当天 `23:59` 计算。**缺少名称或有效截止时间的数据会被丢弃**，并在调试控制台打印警告。

**字段别名**：`src/services/agent.ts` 与 `src/services/team.ts` 中的 `normalizeActivity`、`normalizeTeam` 已兼容常见别名（如 `title`、`recruit_deadline`），后端字段名不同时只改这两处。

**搜索依赖列表字段**：组队页的搜索在本地进行，列表接口需要带上详情字段，否则搜不到详情内容。数据量很大时，应改为把关键词传给后端搜索并分页。

### 6.5 配置与 Mock 切换

在 `.env.development` 中填写（该文件已在 `.gitignore`）：

```bash
TARO_APP_AGENT_BASE_URL=https://后端域名
TARO_APP_AGENT_API_ID=你的 API ID
TARO_APP_AGENT_API_KEY=你的 API Key
```

三项都填写真实值后，应用自动切换到真实接口，页面顶部的黄色「当前为 Mock 数据」提示随之消失，这就是切换成功的标志。未填写时使用内置 mock 数据，方便单独调试 UI。

两个容易混淆的 ID：`project.config.json` 里的 `appid` 是**飞书小程序的 App ID**；`AGENT_CONFIG.apiId` 是**后端 Agent 的 API ID**，两者无关。

### 6.6 域名与安全

- 后端域名必须是 `https`，并在飞书开放平台「开发配置 → 安全设置 → 服务器域名」中添加。开发阶段可在开发者工具详情中勾选「不校验合法域名」。
- **小程序包内的任何字符串都能被反编译提取**。上线前强烈建议由后端网关持有真实 API Key，前端只携带用户登录 code 或短期 token，届时只需改 `baseUrl` 与请求头。
- 飞书应用的 `App Secret` 只能保存在后端，绝不能出现在小程序代码中。

## 7. 飞书机器人与消息卡片

### 7.1 新活动提醒流程

```
爬虫发现新活动 → 入库 → 后端调用发送消息接口（机器人身份）
→ 用户在会话中收到卡片 → 点击「查看详情」
→ 打开小程序 pages/index/index?activityId=xxx → 自动弹出该活动详情
```

机器人与小程序使用**同一个飞书应用**（同一个 `cli_...`）最为简单，需要在开放平台同时开通「机器人」与「小程序」能力。

### 7.2 开放平台配置

1. 添加「机器人」应用能力。
2. 申请「以应用身份发消息」权限（`im:message:send_as_bot`），并发布版本使权限生效。
3. 确认接收对象：群聊用 `chat_id`，个人用 `open_id`（`open_id` 按应用隔离，必须是本应用下获取到的）。
4. 接收人需在应用的可用范围内，否则发送失败。

### 7.3 后端要点

- 通过 `tenant_access_token`（内部应用凭证，需缓存并提前刷新）调用发送消息接口，消息类型为 `interactive`，`content` 必须是 JSON **字符串**。
- 卡片按钮使用飞书 applink 打开小程序，路径形如 `pages/index/index?activityId=xxx`。applink 的参数格式请对照飞书开放平台「applink 协议」文档核对。
- 推送需要**去重**（同一活动只推一次）和**限速**，避免触发频率限制。
- 卡片中的活动 `id` 必须与列表接口返回的 `id` 完全一致。

### 7.4 组队申请流程

```
用户点击「申请」→ 小程序 POST /v1/teams/apply
→ 后端校验需求是否存在、是否已结束、是否重复申请
→ 后端用机器人私信需求发布者（含项目名、申请人、留言）
```

发布者的 `open_id` 只保存在后端，前端不接触。识别申请人需要后端用小程序登录 `code` 向飞书换取用户身份，具体接口请对照飞书开放平台的小程序登录文档。若暂时无法实现，可先让申请人在留言里写明姓名和联系方式。

## 8. 联调检查清单

1. 开发者工具中 `es6` 已勾选，`appid` 为真实值。
2. `.env.development` 三项已填写，且已重启 `dev:tt`。
3. 页面顶部黄色 Mock 提示已消失。
4. 活动列表与组队列表能显示真实数据，状态与排序正确。
5. 控制台没有「丢弃无效数据」警告；有则检查 `deadline` 与名称字段。
6. 本地模拟深链：开发者工具「编译模式」中，页面选 `pages/index/index`，启动参数填 `activityId=某个真实 id`，应自动弹出详情。
7. 真机验证：卡片跳转、Tab 页是否保留 query 参数、Textarea 在弹窗内的层级与键盘遮挡。
8. 申请流程：发布者能收到机器人私信，重复申请被后端拦截。

## 9. 待确认与后续规划

**待确认**

- applink 的具体参数格式与 `mode` 可选值。
- 从深链打开 Tab 页时 query 参数是否保留（活动页现在是 Tab 页）。
- 小程序未发布版本时，通过 applink 打开可能受版本与测试成员限制。
- 小程序已在后台运行时，点击卡片可能不会重新触发页面加载，必要时补充 `useDidShow` 处理。
- Tab 栏目前只有文字，如开发者工具要求图标，需准备 81×81 的 PNG 并配置 `iconPath`。
- 消息卡片目前使用 1.0 结构，如需新特性可改用 2.0 版本。

**后续规划**

- 卡片上直接「关注 / 忽略」，通过卡片回调通知后端。
- 按用户订阅的活动类型定向推送。
- 汇总为每日早报，减少打扰。
- 将搜索条件传给后端，支持分页与服务端搜索。
- 上线前由后端网关代持 API Key。
