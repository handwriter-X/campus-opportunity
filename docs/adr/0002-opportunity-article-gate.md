# ADR 0002：在字段抽取前使用意图识别门控

- 状态：已决定，等待租户导出的 Intent 节点 schema
- 日期：2026-10-14

## 背景

当前工作流中的一个 LLM 同时判断“是不是机会”和抽取机会字段。这样会让非机会文章也进入字段抽取，
并把分类错误和字段错误混在一起。GeniOS 提供「选择器」和「意图识别」两类分支节点，需要先确定哪一个承担文章级门控。

## 决策

使用 **意图识别** 作为第一道门：

```text
Start → 意图识别
          ├─ 机会文章 → 抽取 LLM → parse_and_validate.py ─┐
          └─ 非机会文章 → empty_result.py ────────────────┤
                                                           ↓
                                                          End
```

机会的定义是四类学生可参与机会：竞赛、学术与学习交流、志愿活动与社会实践、校园文体活动。
纯新闻、回顾、喜报和无法确认学生行动的文章判为非机会。非机会分支仍返回统一空结果，worker 正常结束但不入机会库。

## 为什么不是选择器

选择器适合对已经存在的变量做确定性比较，例如 `item_count == 0` 或 `is_opportunity == true`。
它不能单独理解文章正文。因此它可作为后续结果路由，但不能替代第一道文章意图识别。

## 影响

- 抽取 LLM 只处理“机会文章”，提示词职责更单一，非机会文章不会生成机会字段。
- 两条分支必须汇合到同一个 End。当前租户不支持 `VariableAggregator`，因此每个 Code 节点输出对象字段
  `result`，End 直接接收两路对象，worker 递归提取实际执行分支。
- 生成器暂不猜测 Intent 的租户 JSON 字段。用户先在当前租户手动添加 Intent 节点并导出真实 YAML，随后再据此更新生成器和导入文件。
