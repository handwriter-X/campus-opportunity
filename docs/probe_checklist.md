### 步骤 7.1 —— 建一张测试表 [人]

在飞书里建一个多维表格，含一张表，字段刻意覆盖各种类型：

| 字段 | 类型 | 为什么要它 |
| --- | --- | --- |
| 姓名 | 文本 | 普通字段 |
| 校区 | **单选** | 硬筛要用 |
| **技能** | **多选** | **硬筛全靠它，是最关键的一项** |
| 每周投入 | 单选 | 硬筛要用 |
| 经历 | 多行文本 | 语义匹配要用 |
| 负责人 | **人员** | 验证身份字段能否带出 open_id |

手填 3–5 行假数据。

### 步骤 7.2 —— 配置插件并授权 [人]

1. 在 GeniOS 里找到「飞书多维表格_OAuth2 工具授权插件」
2. auth url 默认 `https://accounts.feishu.cn/open-apis/authen/v1/authorize`
3. 走一遍授权流程 —— **记下：授权页要求你用什么账号授权、授了哪些权限范围（scope）**
4. 把多维表格的**链接或 ID** 填进插件配置
5. **确认该表格已把应用设为协作者**（否则 API 会 403/400）

### 步骤 7.3 —— 逐个试工具 [人]

建一个**最小工作流**（Start → 插件节点 → End），按顺序试：

| 试什么 | 期望 | 记下什么 |
| --- | --- | --- |
| `get_base_info` / `list_table` | 能列出表 | 返回里**有没有字段名和字段类型** |
| `search_records`（无条件） | 返回全部行 | **一次最多返回几条？有没有分页？** |
| `search_records`（**筛选：技能 包含 某值**） | 只返回命中的行 | ⭐ **多选字段能不能筛——这是生死线** |
| `search_records`（筛选：校区 = 津南） | 同上 | 单选字段的运算符有哪些 |
| `create_records` | 新增一行 | 成功？字段值怎么传（多选/人员字段怎么写）？ |
| `update_records` | 改一行 | 能否**只改部分字段**（"只补空缺"靠它） |

> 每步**截一张图**，贴到 `docs/findings.md` 的 S7 一节。**报错原文也要**——那是证据。

### 步骤 7.4 —— ⭐ 验证 token 能不能自动刷新 [人]（**生死线**）

**做法**：

1. 授权成功后，**放着不管**（不要重新授权）
2. 隔 **2 小时以上**再看工作流还能不能读写
3. 隔 **一天**再看一次

**判定**：
- ✅ **还能用** → 插件会自动刷新 token → **架构成立**
- ❌ **报鉴权错误** → 每次都要人工重新授权 → **这个方案不能用于生产，必须换路**（退回「gateway 读表 → 送 GeniOS → 取回 → 写表」）

> 原因：飞书 `user_access_token` 通常 **2 小时**过期、`refresh_token` 约 **30 天**。
> 插件若不能自己刷新，稳态运行就会断。

### 步骤 7.5 —— 顺带确认两件事 [人]

| 问题 | 为什么 |
| --- | --- |
| 授权的是**谁的身份**？GeniOS 以谁的名义操作表格？ | OAuth2 是用户授权，大概率是**你自己**。要清楚这一点 |
| GeniOS 有没有**定时触发**？ | 有 → GeniOS 能自主定时跑，才是真正的「智能体」；没有 → 只能外部 cron 叫它（PLAN.md §4 本来就标着这个 ❓） |

## S9 · 小程序前端的入站可达性（2026-10-16 新增）

**目标**：确认能不能给 gateway 一个**稳定、可被飞书白名单固定**的 https 地址 ——
这是「合入 Taro 飞书小程序前端（`mers95395-lab/campus-opportunity-pool`）」的前置。
**CC 侧已测完**，结论与证据见 `docs/findings.md` 的 **S9** 一节。剩下两件事在 [人] 手上。

**已知（[CC] 实测 2026-10-16）**

- ✅ 隧道链路端到端通：公网 URL → gateway `/health` 200
- ❌ 快速隧道 **URL 每次重启都变**、进程一停旧 URL **530** → **加不进白名单**
- ❌ 本机无公网 IP（`192.168.190.128/24`，VMware NAT）、`~/.cloudflared/` 不存在（没登录、没域名）

### 步骤 9.1 —— 【关键】在控制台实测「服务器域名」的要求 [人]

打开飞书开放平台 → 你的自建应用 →「**开发配置 → 安全设置 → 服务器域名**」，
**试着加一个域名**，看控制台要求什么：

| 要确认 | 为什么要 |
| --- | --- |
| 是否必须 **https** | 决定能不能直接用隧道 |
| **是否要求 ICP 备案**（要备案主体/备案号） | **决定海外域名能不能用** —— 若强制备案，命名隧道那条路的域名也得国内备案 |
| 能否加**通配/二级域名** | 决定要不要为隧道单独买域名 |
| 加完之后**真机**（不是开发者工具）能否请求通 | 「不校验合法域名」只在工具里有效 |

> **把截图或报错原文贴回 `docs/findings.md`。** 这是关闭本探针**唯一缺的证据** ——
> 官方文档这次没取到（JS 渲染），不要拿微信/阿里系平台的规则套飞书。

- **命名隧道**：需要 Cloudflare 账号 + **一个自有域名**（`cloudflared tunnel login` → `tunnel create` → 加 DNS 记录）。

### 步骤 9.3 —— 决定飞书应用是否合并 [人]

小程序自带的 appid（`cli_aa4532d4c4f8dbe1`）与我们现有自建应用（`cli_aa4ede…`）**不是同一个**。
**`ou_` open_id 按应用隔离** —— 不统一，小程序换来的 open_id 与多维表格人员字段对不上，
**申请无法归因，且不报错**。⇒ 机器人 + 小程序应合并到同一个应用。

> **合入小程序这件事本身要先拍板**：它推翻 D9「不需要公网」的前提，
